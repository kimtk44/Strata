Findings
- Two cards: cold prefill +76%; decode unchanged because the pipelined decode stayed OFF. Auto (`pipeline_windows=-1`) needs 3 stages unless the MTP drafter sits on the first card (mtp_first), and it prints nothing when it decides off.
- F04 works (b2 logs "--pcie-frac 0: the verify windows skip the PCIe share path", b3 does not) but is noise-level here: on two cards 85% of experts are resident and decode cache hit is 97.7-98.9%, PCIe reads 0.1-0.3% of routed experts. F04 matters only when residency is lower (one card / longer context / bigger quant).
- One card: ~23.2 GB VRAM, load 50-65 s. Two cards: 23.0 + 23.1 GB, load 65-75 s.
- Answers not yet scored against answer-key.md.

Pipelined decode (rerun 11-19 ~21:00 KST, foreground, RAM-short env HSA_USERPTR_FOR_PAGED_MEM=0 STRATA_RESIDENT_PIN=0 GPU_PINNED_MIN_XFER_SIZE=1048576 + STRATA_MTP_STAGE0=1, all step0)
- Root cause of "pipeline does nothing": the server's model-card instruct default (http_api.py MODEL_CARD_SAMPLING qwen4exp) adds presence_penalty 1.5 to every thinking-off request without its own penalty, and any penalty makes --pipeline-windows decode serially ("a request with repetition penalties (penalty_last_n) decodes serially", printed once). Thinking-on requests get no card penalty. The kit is thinking off, so b1-b4 all decoded serially.
- qa_np.py = the kit with presence_penalty=0 per request.

- Pipeline +~20% decode over serial (matches #4136's 66-71 -> ours higher). Penalty 0 alone +~8% over penalty 1.5.
- Answers differ run to run at temperature 0.7 (also b4np vs b5np), not a pipeline defect; bit-exact check needs STRATA_IQ_MT_MIN=1.
- F04 on vs off under the pipeline: small edge for on, within noise.
- RAM: engine RSS peaks 48.6 GiB, MemAvailable down to 1.1 GiB; driver pauses of 2-30 s ("paused the GPU ... while Linux moved memory"). This is the cost on a 64 GB box with the session's other processes; the always-on server should leave more headroom.
